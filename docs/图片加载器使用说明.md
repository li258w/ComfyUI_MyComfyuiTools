# 图片加载器使用说明（ComfyUI_MyComfyuiTools）

从文件夹**每次读一张图**，处理完后删掉它，自动读下一张，直到目录清空。

三个节点都在右键菜单 → `MyCustomNodes/Image` 下：

| 节点 | 作用 |
|---|---|
| `加载图片·文件夹队列 (读完可删除)` | 读图 + 推进进度，可选读完即删 |
| `确认删除图片 (收尾)` | 等流程跑完（图片存好）后再删源文件 |
| `图片队列进度查询` | 只看进度，不读图（可选） |

---

## 一、两种用法，二选一

### 模式 A：读完即删（简单）

只要加载节点自己就行。

```
[加载图片·文件夹队列 after_load=delete] → IMAGE → 处理流程 → 保存图片
```

- 加载节点**不是** OUTPUT_NODE，**后面必须接保存或预览节点**，否则 ComfyUI 不会执行它
  （ComfyUI 只跑"输出节点的祖先链"）
- 代价：**没有产物确认**。流程中途崩了，源图也已经删了

### 模式 B：确认出图成功后才删（安全，推荐）

```
[加载图片·文件夹队列 after_load=keep] → IMAGE → 处理流程 → 保存图片
        │                                  │
        └─ file_path ─────────┐            └─ IMAGE ─┐
                              ▼                      ▼
                     [确认删除图片: file_paths + image]
```

**加载节点的 `after_load` 必须设成 `keep`。** 设成 `delete` 的话，文件在流程刚起步就被删了，
收尾节点拿到路径时文件已经不存在，只会显示"已删除 0 个文件｜1 个不存在"。

放心，`keep` 也会推进进度，不会卡在同一张——它只是把"删除"这个动作从"读完时"
挪到了"流程末端"。

---

## 二、收尾节点怎么连线

| 从 | 到 | 作用 |
|---|---|---|
| 加载节点右侧 **`file_path`** 圆点 | 收尾节点 → 选 **`file_paths`** | 告诉它删哪个文件 |
| 处理流程末端的 **`IMAGE`**（就是已连到保存图片的那根，再分一条） | 收尾节点 → 选 **`image`** | 确保整条流程算完才轮到它 |

拖线时把线拉到收尾**节点体上松手**，会弹出输入列表让你选。
没反应的话：右键收尾节点 → `Convert Widget to Input` → `file_paths`，再连。

`image` 是**可选**的，不接也能跑，只是少一层时序保证。

---

## 三、收尾节点参数速查

| 参数 | 建议值 | 说明 |
|---|---|---|
| `file_paths` | 接 `file_path`，或手填 | 多个路径用换行/逗号/分号隔开 |
| `image` | 接处理链末端 IMAGE | 可选，建立"流程已完成"的依赖 |
| `enabled` | **先 `False` 空跑**，验证后改 `True` | 关掉时只报告不删除 |
| `confirm_output` | `D:\...\output\你的前缀_*.png` | 产物确认，见下方注意 |
| `wait_seconds` | 3 | 产物还没出现时最多等几秒 |
| `backup_first` | 第一次用设 `True` | 删前复制到 `<源目录>/_backup/` |
| `on_missing` | `skip` | 源文件已不在时警告继续 / `error` 报错中断 |
| `rollback_on_skip` | `True` | 跳过删除时撤回已读记录，下次重读，不会漏处理 |

### ⚠ confirm_output 的坑

**不要只填目录**（如 `...\output`）。那样它判断的是"目录里有没有图片"——里面本来就有
以前生成的图，于是即使这次保存失败也会误判成"产物已生成"，照样删。

要真正确认"这一张存好了"，就用**带文件名前缀的通配符**：

```
D:\AI\ComfyUI_windows\ComfyUI_windows_portable\ComfyUI\output\你的前缀_*.png
```

---

## 四、两个节点能单独用吗

都能，但方式不同：

| 用法 | 加载节点 | 收尾节点 | 说明 |
|---|---|---|---|
| 读完即删 | `delete`，需接保存/预览 | 不用 | 最简单，无确认保护 |
| 确认后删 | `keep`，需接保存 | 必用 | 安全，推荐 |
| 只删一批文件 | 不用 | **手填路径** | 当带确认的批量删除工具 |

收尾节点是 **OUTPUT_NODE**，就算在画布上孤零零一个也会执行，而且 `file_paths`
可以直接手填任意路径，不必依赖加载节点。

---

## 五、删掉的文件去哪了

- 优先送**系统回收站**，可在回收站还原
- **非 NTFS 卷**（exFAT U 盘、网络盘）没有回收站 → 自动改成移动到 `<源目录>/_trash/`
- 图片**读取失败时不删除**，也不推进进度

---

## 六、进度与重置

- 记录文件：`<源目录>/.comfy_imageloader_state.json`（源目录不可写时退回插件目录 `states/`）
- 记的是**已读文件的相对路径**，中途往目录加新图、或换排序方式都不会错位
- 目录读完后会**报错中断**，防止空跑
- 重新开始（三种方式任选）：
  1. 加载节点 `reset_progress` 打开再跑一次
  2. 点加载节点上的 **🔄 重置进度** 按钮
  3. 直接删掉 `.comfy_imageloader_state.json`

---

## 七、第一次用的安全流程

1. 加载节点 `after_load = keep`，收尾节点 `enabled = False`
2. 跑一次 → 收尾节点应显示 `⏸ 已跳过：enabled=False`
3. 把 `confirm_output` 临时改成瞎编的路径，再跑 → 应显示 `⚠ 未检测到产物…，已跳过删除`
4. 两条都对上了，再把 `enabled` 打开正式跑

---

## 八、安装位置与文件结构（重要）

图片加载器是 **`ComfyUI_MyComfyuiTools` 插件的一个模块**（v2.5 起），不是独立插件目录：

```text
V0.7.0\ComfyUI\custom_nodes\ComfyUI_MyComfyuiTools\
├── __init__.py                 # 合并注册节点 + 注册 /mycomfyuitools/imageloader/* 路由
├── image_loader_core.py        # 扫描 / 排序 / 进度 / 删除
├── image_loader_nodes.py       # 3 个节点类
├── js/image_loader.js          # 缩略图预览 / 文件夹浏览 / 重置进度
└── selftest_image_loader.py    # 自测脚本
```

- `V0.7.0\ComfyUI\custom_nodes\ComfyUI_MyComfyuiTools` ← **实体在这里，改这里**
- `ComfyUI_windows_portable\ComfyUI\custom_nodes` ← 不生效，不用管
